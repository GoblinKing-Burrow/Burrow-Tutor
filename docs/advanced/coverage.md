This matrix inventories the **ordinary third-party mod surface documented by Tutor today**. It deliberately excludes privileged `context.modManagement` and `context.processExecution`, except for boundary notes. “Current-Core verification” means exactly what `test/core-contract.test.mjs` executes against the sibling `Burrow-Backend` checkout—not what activation makes theoretically callable.

Legend:

- **invoked**: the current-Core integration test executes the behavior;
- **activation only**: current Core discovers/registers the surface, but the capability itself is not exercised;
- **not exercised**: no current-Core integration assertion for that behavior;
- **docs only in Tutor**: Core exposes/documents the surface, but Tutor has no runnable example (not a claim that Core lacks implementation).

## Explicit Tutor documentation-only surfaces and real gaps

These are current documented host surfaces, but there is no runnable Tutor implementation for them today:

- manifest `managedSkills` contributions and bundled skill packages;
- full product examples for Settings host arguments `runtimeScope`, `accessApi`, `refreshAgents`, and `saveAgentExecutionEnvironment` (the standalone declarative factory does demonstrate `agents`);
- a dedicated four-concurrent-capability/timeout/shutdown stress example;
- `displayMessage`, turn cancellation, and mod-owned session creation/model controls (available in Core, not exposed by Tutor’s lab).

The following have runnable Tutor code but still lack substantive production integration for some layers: diagnostic HTTP adapter endpoints, persistent mod-data through lifecycle update/uninstall, the outer protected-value registry and shell consumption, encrypted PostgreSQL secret storage, and browser UI mounting. Agents/operator, conversations, models, scheduler, invocation-scoped diagnostics, and both protected declaration/resolver forms now cross the current forked host and Core capability service with controlled stores/providers. `npm run test:core` proving activation/registration must not be reported as behavior verification for those surfaces.

## Privileged exclusions

`context.modManagement` (`mod-management-v1`) and `context.processExecution` (`execution-provider-v1`) are intentionally absent from all runnable Tutor code and from the ordinary matrix. A regular manifest must not declare `systemCapabilities`. System classification, installation, MCP grants, diagnostic IDs, or `mod-authorized` availability do not grant these interfaces.

## Run the checks

```sh
npm run build
npm test
npm run test:core
```

By default `test:core` resolves the sibling checkout at `../Burrow-Backend`; override with `BURROW_CORE_ROOT=/absolute/path` when needed. Its Forge backend is an in-memory fixture and makes no paid provider call.
